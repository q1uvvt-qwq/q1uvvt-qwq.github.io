##  工控前置

### OT

OT（Operational Technology，运营技术）是直接监测或控制物理过程的技术系统。

例如：

- 控制水泵启停。
- 调节阀门开度。
- 监测水位、温度和压力。
- 控制风机转速。
- 操作变电站断路器。
- 调节生产线传送带速度。

普通 IT 系统主要处理信息；OT 系统处理信息以后，通常会影响现实世界。

```
IT：修改数据库记录
OT：修改寄存器 → 水泵启动 → 水位上升
```

因此，OT 安全事件可能造成：

- 生产中断。
- 设备损坏。
- 产品质量变化。
- 环境污染。
- 人员安全事故。



### ICS

ICS（Industrial Control System，工业控制系统）是用于监视和控制工业过程的一类系统总称。

ICS 通常包括：

- PLC。
- RTU。
- HMI。
- SCADA。
- DCS。
- 工程师站。
- 传感器与执行器。
- 工业网络与协议。

ICS 属于 OT，但 OT 的范围更广，还包括楼宇控制、交通控制、物理门禁等系统。



### SCADA、DCS 与 PLC

它们不是互相替代的同类产品。

- PLC：直接运行控制逻辑。
- SCADA：集中监视多个远程站点。
- DCS：在工厂内部对连续生产过程进行分布式控制。
- HMI：给操作员提供画面和操作入口。

以泵站为例：

```
液位传感器
    ↓
PLC 判断液位是否过低
    ↓
PLC 启动进水泵
    ↓
HMI 显示水泵状态
    ↓
SCADA 保存历史趋势并产生告警
```



## 认识工控系统中的主要资产

#### 传感器

传感器负责把物理世界转换为可读取的数据。

典型对象：

- 温度。
- 压力。
- 流量。
- 液位。
- 转速。
- 电压与电流。
- 阀门位置。

传感器输出可能是模拟量、数字量，也可能通过现场总线或工业以太网发送。

在蜜罐研究中，不能只生成随机传感器数值。不同变量通常存在物理关联，例如：

```
泵启动
→ 进水流量增加
→ 水箱液位逐渐升高
→ 达到高液位后产生告警或停止泵
```

如果泵显示停止，但流量和水位仍持续高速上升，就容易暴露仿真不真实。



#### 执行器

执行器负责改变物理过程，例如：

- 水泵。
- 电机。
- 阀门。
- 加热器。
- 断路器。
- 继电器。

攻击者修改 PLC 输出或控制参数后，最终通常要通过执行器影响物理过程。



#### PLC

PLC 是现场控制的核心设备。它周期性执行：

```
读取输入
→ 执行控制程序
→ 更新输出
→ 进行通信和诊断
→ 进入下一周期
```

这个过程叫扫描周期。

PLC 不是普通服务器。它强调：

- 周期执行。
- 确定性。
- 稳定运行。
- 与现场输入输出直接关联。
- 长时间持续运行。

PLC 执行的是控制逻辑；执行器执行的是物理动作。

以水箱控制为例：

```
液位传感器 → PLC → 水泵/阀门
               决策      动作
```

| 对比项   | PLC                             | 执行器                                 |
| -------- | ------------------------------- | -------------------------------------- |
| 本质     | 工业控制计算机                  | 改变物理过程的设备                     |
| 输入     | 传感器数据、HMI 命令、控制程序  | PLC 输出的控制信号                     |
| 执行内容 | 判断、计算、逻辑和状态转换      | 启停、转动、开关、移动、加热           |
| 输出     | 电气信号、寄存器值或通信命令    | 流量、压力、位移、转速、温度等物理变化 |
| 典型设备 | Siemens S7、施耐德 PLC、OpenPLC | 电机、水泵、阀门、继电器、加热器       |

例如，PLC 中可能有一条逻辑：

```
如果水位低于 30%，并且系统不是故障状态，则启动水泵。
```

执行过程是：

1. 液位传感器告诉 PLC：当前水位为 25%。
2. PLC 执行程序，判断需要启动水泵。
3. PLC 将某个输出点设置为 `1`。
4. 接触器或变频器接收这个信号。
5. 水泵实际转动，水位开始上升。

其中：

- PLC “执行启动水泵的控制逻辑”。
- 水泵“执行抽水这个物理动作”。

#### RTU

RTU 常用于地理上分散的远程站点，如：

- 输油管线。
- 电力变电站。
- 水务泵站。
- 风电场。
- 环境监测站。

RTU 与 PLC 的边界在现代系统中并不绝对，但 RTU 通常更强调远程通信、遥测和恶劣环境适应能力。



RTU 经常把以下能力集成在一台设备中：

- 采集数字量和模拟量。
- 控制现场输出。
- 运行有限或较复杂的控制逻辑。
- 缓存历史数据和事件。
- 处理告警。
- 与远程 SCADA 通信。
- 在通信中断时维持本地控制。

因此，它确实具有一些类似 PLC 的功能。但更准确的表达是：

> RTU 集成了远程通信、现场数据采集和一定程度的控制能力。



```
远端站点：一整套现场系统
RTU：站点里的数据采集、控制与远程通信核心
传感器/执行器：与物理过程直接交互的现场设备
```

例如一个远程泵站：

```
                 SCADA 中心
                     ↑
                4G/专线/无线
                     ↑
压力传感器 → RTU → 水泵、阀门
液位传感器 ↗  ↘
             本地告警与数据缓存
```



#### IED

IED（Intelligent Electronic Device）常见于电力系统，例如：

- 保护继电器。
- 智能电表。
- 故障录波装置。
- 断路器控制装置。

如果以后研究风电或电力蜜罐，IED、IEC 104、IEC 61850 会成为重要内容。



#### HMI

HMI 是操作员界面，负责：

- 显示工艺流程。
- 展示实时数据。
- 显示告警。
- 下发启停或参数调整命令。
- 查看趋势和设备状态。

HMI 通常不直接完成底层控制逻辑，实际控制仍主要由 PLC 或 DCS 控制器执行。



#### 工程师站

工程师站（Engineering Workstation，EWS）是工程师用来配置、编程、调试和维护工控系统的计算机。

简单来说：

> HMI 用于“操作生产”，工程师站用于“修改控制系统本身”。

工程师站负责：

- 编写或修改 PLC 程序。
- 下载程序到 PLC。
- 修改硬件组态。
- 调试设备。
- 管理项目文件和控制参数。

工程师站通常比普通 HMI 权限更高，因此也是高价值攻击目标。

在系统中的位置

```
                 工程师站
                    │
             编程、组态、诊断
                    ↓
传感器 → PLC/RTU → 执行器
           ↑
           │ 日常监视与操作
          HMI
           │
         SCADA
```

工程师站一般不直接驱动水泵或阀门，而是修改 PLC 中决定水泵和阀门如何工作的程序。

#### Historian

Historian，即工业历史数据库，用于长期保存：

- 过程变量。
- 告警。
- 操作记录。
- 产量与质量数据。
- 设备运行趋势。



## 控制回路和物理过程

### 基本控制回路

控制回路通常包含：

```
设定值 Setpoint
      ↓
控制器比较设定值与测量值
      ↓
产生控制输出
      ↓
执行器改变物理过程
      ↓
传感器产生新的测量值
      └────────反馈到控制器
```

以水箱为例：

- 设定值：水位保持在 60%。
- 测量值：当前水位为 42%。
- 控制器：判断水位偏低。
- 控制输出：启动进水泵。
- 物理过程：水位逐渐上升。
- 反馈：液位传感器持续返回新水位。



### 开环与闭环控制

开环控制不根据结果修正动作：

```
启动水泵 10 秒
→ 不关心水位最终是多少
```

闭环控制根据测量结果持续修正：

```
水位低于 50%
→ 启动水泵
→ 水位达到 70%
→ 停止水泵
```

蜜罐如果要模拟真实控制过程，至少需要表现出基本的闭环一致性。



### 状态与状态转换

工业设备通常不是只有“开”和“关”，还可能包括：

- stopped
- starting
- running
- stopping
- fault
- maintenance
- emergency_stop

状态转换必须合理：

```
stopped → starting → running
running → fault
fault → reset → stopped
```

不合理情况包括：

- fault 状态直接切换到 running。
- 水泵未启动却产生满负荷流量。
- 急停后执行器仍接受普通启动命令。
- 设备关闭后温度、压力瞬间归零。



## Purdue 模型

Purdue 模型用于描述工业系统的逻辑分层。不同企业的实际架构可能不同，因此应把它当作分析模型，而不是绝对的网络模板。

### Level 0：物理过程

包括：

- 水流。
- 温度。
- 压力。
- 风机叶片。
- 电机转速。
- 化学反应。
- 生产线运动。

这一层是最终被控制的现实对象。

### Level 1：基本控制

包括：

- PLC。
- RTU。
- IED。
- 传感器。
- 执行器。
- 变频器。

主要任务是执行实时控制。

### Level 2：监控与操作

包括：

- HMI。
- SCADA 操作站。
- 本地控制服务器。
- 告警服务器。

主要供操作员查看和控制生产过程。

### Level 3：生产运营

包括：

- Historian。
- 工程师站。
- 资产管理。
- 补丁和软件管理。
- 生产调度。
- OT 域服务。

### Level 3.5：工业 DMZ

这不是原始 Purdue 模型的正式编号，但工程实践中经常使用。

常见资产包括：

- 跳板机。
- 文件中转服务器。
- 日志转发服务器。
- 远程访问网关。
- 安全监测设备。
- Historian 副本。
- 更新代理。

工业 DMZ 的目的不是直接控制生产，而是隔离企业网和控制网之间的通信。

**工业 DMZ 中通常放什么**

**1. 跳板机**

外部维护人员不能直接连接 PLC、SCADA 或工程师站，而是：

```
运维人员
   ↓ 身份认证
DMZ 跳板机
   ↓ 审计后的受控会话
OT 运维目标
```

跳板机通常负责：

- 多因素认证。
- 账号权限控制。
- 会话录像。
- 操作审计。
- 文件传输限制。

**2. Historian 副本或数据中转服务器**

OT 中的实时数据库将经过筛选的生产数据同步到 DMZ，企业系统只读取 DMZ 中的副本。

```
OT Historian → DMZ 数据副本 → 企业报表系统
```

**3. 文件中转服务器**

补丁、配置文件和软件不能直接从办公网送到工程师站，通常先进入 DMZ：

```
企业网文件
→ DMZ 隔离区
→ 杀毒、审批、完整性检查
→ OT 网络
```

从 OT 导出的日志和文件也经过类似流程。

**4. 日志中转服务器**

OT 设备的日志可先集中到 DMZ，再发送给企业侧 SOC 或 SIEM：

```
PLC/SCADA/防火墙日志
→ DMZ 日志中转
→ 企业安全监测平台
```

**5. 远程访问网关**

用于供应商或远程维护人员的受控接入。它不应允许用户从互联网直接进入 PLC 网络。

**6. 安全更新服务**

DMZ 中可以放置：

- 补丁缓存。
- 杀毒特征库中转。
- 软件仓库镜像。
- 时间或证书服务的代理节点。

### Level 4：企业 IT

包括：

- 办公网络。
- ERP。
- 邮件系统。
- 财务系统。
- 企业身份系统。

### Level 5：外部或云环境

可能包括：

- 供应商远程服务。
- 云分析平台。
- SaaS 系统。
- 互联网。
- 外部合作机构。

### 典型拓扑

```
Level 5  互联网、云平台、供应商
                  │
Level 4  企业办公网、ERP、邮件
                  │
Level 3.5 工业 DMZ、跳板机、日志中转
                  │
Level 3  工程师站、Historian、生产管理
                  │
Level 2  SCADA、HMI、告警服务器
                  │
Level 1  PLC、RTU、IED
                  │
Level 0  传感器、泵、阀门、物理过程
```

## 流量和协议

工控网络中的流量至少分为五类。

### 1. 控制流量

```
HMI/SCADA → PLC
```

例如：

- 启停设备。
- 修改设定值。
- 调整阀门开度。
- 确认告警。

### 2. 遥测流量

```
PLC/RTU → HMI/SCADA/Historian
```

例如：

- 温度、压力、液位。
- 开关状态。
- 电机电流。
- 告警和故障码。

### 3. 工程流量

```
工程师站 → PLC
```

例如：

- 下载控制程序。
- 修改配置。
- 读取诊断信息。
- 升级固件。

这类流量往往比普通 HMI 操作权限更高。

### 4. 管理流量

例如：

- 时间同步。
- 日志传输。
- 身份认证。
- 资产发现。
- 补丁与软件分发。

### 5. 业务数据流

```
生产网络 → 工业 DMZ → 企业网络
```

企业系统通常需要产量、能耗和质量数据，但一般不应直接连接现场 PLC。

### 协议的位置

现阶段只需要理解协议用途：

| 协议        | 常见用途                   |
| ----------- | -------------------------- |
| Modbus TCP  | PLC、RTU、仪表的寄存器读写 |
| S7comm      | Siemens PLC 通信           |
| OPC UA      | 结构化工业数据交换         |
| IEC 104     | 电力远动与调度通信         |
| IEC 61850   | 变电站自动化               |
| DNP3        | 电力、水务等远程监控       |
| EtherNet/IP | 工业设备和 PLC 通信        |
| MQTT        | IIoT 消息传输              |
